# Worko — наряды под контролем ИИ

Решение **кейса №1** республиканского хакатона **Qostanai AI Industry Hackathon 2026**
Организатор кейса: АО «Костанайские минералы»

**Демо:** https://letsgobek.github.io/worko/
**Демо-доступ:** исполнитель — табельный `4417`, ПИН `1234` · мастер — табельный `1102`, ПИН `5678`

---

## Проблема

На предприятии наряды выдаются устно, по рации или на бумаге. Из-за этого:

- наряды теряются, срочные работы ждут своей очереди;
- мастер не видит в реальном времени, кто свободен и что выполняется;
- нет подтверждения выполнения — ни фото, ни списанных материалов;
- простои оборудования и их причины не считаются;
- повторяющиеся поломки одного узла не замечают, пока они не становятся аварией;
- нет объективной оценки работы исполнителей.

## Решение

Worko переводит весь цикл наряда в телефон и поручает ИИ контроль сроков, проверку качества и поиск закономерностей.

| Роль | Устройство | Что делает |
|---|---|---|
| Мастер смены | телефон + веб-панель | создаёт и выдаёт наряды, видит статусы, принимает работу |
| Исполнитель | телефон | получает наряды, меняет статусы, закрывает с фото и материалами |
| Руководитель | веб-панель | аналитика, рейтинги, простои |
| Администратор | веб-панель | справочники: участки, оборудование, сотрудники, шифры |

### Жизненный цикл наряда

```
Выдан → Принят → В работе → Исполнено → Проверка ИИ → Закрыт
   ↓        ↓          ↓                      ↓
В очереди  Отклонён  Приостановлен       На доработку
```

Каждый переход фиксируется со временем и автором в журнале действий.

## ИИ-модули

| Модуль | Что делает |
|---|---|
| Контроль сроков | напоминание до срока, сообщение о просрочке исполнителю и мастеру, эскалация при отсутствии ответа (3 мин для аварийных, 10 мин для остальных) с автоматической передачей другому исполнителю |
| Проверка выполнения | сверяет описание работ с описанием проблемы, проверяет полноту закрытия, логичность списанных материалов, время против норматива; выносит вердикт и оценку 1–5 с пояснением |
| Анализ фото | проверяет наличие и свежесть снимка «после», сравнивает с фото «до» |
| Отчёт по наряду | исполнителю — что сделано хорошо, что улучшить, факт против норматива; мастеру — полная карточка с хронологией |
| Аналитика истории | топ проблемного оборудования, повторяющиеся отказы одного шифра, аномальный расход материалов, зависимость от смены и исполнителя |
| Прогноз отказов | сравнивает последние 30 дней с предыдущими; при росте внеплановых нарядов предупреждает о вероятном отказе |
| Ассистент мастера | отвечает на вопросы о смене обычным языком: кто свободен, что просрочено, какое оборудование проблемное |
| Рейтинг | качество 40% · в срок 30% · без доработок 20% · объём 10%; ИИ поясняет каждому, из чего сложился балл |

**Решения ИИ — рекомендация. Финальное слово всегда за мастером:** он может согласиться с оценкой, изменить её или вернуть наряд на доработку.

## Возможности

- выдача наряда с телефона за 5 нажатий, голосовой ввод описания
- подсказка ИИ по исполнителю, шифру неисправности и нормативу времени
- статусы исполнителей и канбан нарядов в реальном времени
- push-уведомления, аварийные наряды с обратным отсчётом на ответ
- фото «до» и «после» прямо с камеры
- приостановка наряда с причиной из списка или своим текстом
- QR-код на оборудовании: навёл камеру — открылась его история
- история и журнал по каждому наряду и каждой единице оборудования
- отчёт за смену, рейтинг, аналитика с выгрузкой в PDF
- три языка интерфейса: русский, қазақша, English
- светлая и тёмная тема, работа без сети
- вход по табельному номеру и ПИН-коду, разграничение прав по ролям

## Технологии

| Слой | Решение |
|---|---|
| Клиент | PWA, HTML + CSS + JavaScript без зависимостей, ставится на главный экран Android и iOS |
| Сервер и база | Supabase: PostgreSQL, Realtime, Auth, Storage |
| Реальное время | Supabase Realtime, обновление статусов до 5 секунд |
| ИИ — тексты, вердикты, отчёты | Claude API |
| ИИ — фото | мультимодальная модель, сравнение «до/после» |
| ИИ — аномалии | статистика по истории нарядов |
| Офлайн | Service Worker, действия сохраняются и отправляются при появлении сети |

## Запуск

### Быстро, без сервера

```bash
git clone https://github.com/letsgobek/worko.git
cd worko
python3 -m http.server 8080
```

Открыть `http://localhost:8080`. Данные хранятся в браузере — этого достаточно, чтобы пройти весь цикл наряда.

### С базой данных

1. Создать проект на [supabase.com](https://supabase.com)
2. SQL Editor → выполнить по порядку: `db/schema.sql`, `db/seed.sql`, `db/storage.sql`, `db/rls.sql`
3. Authentication → Users → создать пользователей вида `<табельный>@worko.kz` с паролем `worko<ПИН>`
4. SQL Editor → выполнить `db/auth.sql` — свяжет пользователей с сотрудниками
5. Скопировать `config.example.js` в `config.js`, подставить Project URL и anon-ключ
6. Запустить любой статический сервер из корня репозитория

### ИИ-проверка через Claude

Ключ Anthropic хранится в секретах Supabase и в браузер не попадает.

```bash
npm i -g supabase
supabase login
supabase link --project-ref <ref проекта>
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
supabase functions deploy ai-review --no-verify-jwt
```

Если функция не задеплоена, приложение считает вердикт по встроенным правилам — цикл наряда работает в любом случае.

### Публикация

GitHub Pages: Settings → Pages → Source: ветка `main`, папка `/root`.
Сайт откроется по адресу `https://letsgobek.github.io/worko/`.

### Сборка APK

PWA ставится на Android через «Добавить на главный экран». Для установочного файла:
[pwabuilder.com](https://www.pwabuilder.com) → вставить ссылку на сайт → Android → скачать APK.

## Тестовые данные

4 участка, 13 единиц оборудования, 8 сотрудников, 8 шифров неисправностей, 7 позиций материалов, 500+ нарядов за 90 дней.

В историю намеренно заложены закономерности, которые ИИ должен обнаружить:

1. конвейер К-3 ломается втрое чаще остальных, в основном по шифру М-02;
2. у одного исполнителя доля возвратов на доработку втрое выше средней по смене;
3. в ночную смену завышен расход масла по шифру Г-04.

## Эффект для предприятия

- меньше простоев: причина поломок устраняется, а не её следствие;
- быстрее реакция на аварии: обратный отсчёт и автоматическая передача наряда;
- прозрачная загрузка персонала и объективный рейтинг;
- данные для планирования ППР вместо таблиц в Excel;
- персональные данные не передаются во внешние сервисы без обезличивания;
- архитектура допускает интеграцию с 1С:ТОИР, уже внедрённой на предприятии.
